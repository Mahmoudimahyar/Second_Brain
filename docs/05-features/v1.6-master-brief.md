# V1.6 Master Brief

> **Status:** Spec only. Drafted 2026-05-27 by Claude per Mahyar's V1.6 kick-off request (website-crawl ingestion). Implementation blocked on per-sub-slice TDD per AGENTS.md, on V1.5c Verification Before Completion report being filed, and on ADR-019 + ADR-020 ratification.
>
> **Reframe from V1.5:** V1.5 closed three deltas — generalized DB connectors, web UI + multi-level graph views, and web-search-grounded conflict resolution + per-team dashboards. V1.6 opens the door to **user-driven non-database external sources** by adding (a) a scheduled multi-domain website-crawl data source, (b) a staged graph-ingestion pipeline aligned with V1's 5-pass architecture, and (c) UI surfaces to register, schedule, and inspect crawled domains.

## What V1.6 is for

V1.5 generalized "where data comes from" for **structured stores** (Postgres / MySQL / SQLite / Neo4j). The forum data still requires a one-shot manual dump per the V1 Reddit / SDN adapters. V1.6 is the **continuous external-content pass**: the user names domains they want SecBrain to keep up with, picks a refresh cadence, and the system handles fetch → normalize → stage into the graph on its own.

V1.6 is the first slice where SecBrain has an **autonomous outbound surface** that talks to the open web on a schedule. That makes it the slice where the long-deferred "crawler (separate system)" placeholder in `docs/04-architecture/system-overview.md` §"External integrations" finally lands inside the engine — but **only for whitelisted official-source domains**, not forums.

V1.6 stays internal-only (single-user, localhost) per ADR-009; multi-tenant rewrites remain V2.

## Architecture deltas from V1.5

The engine internals stay the same. What V1.6a adds:

**New `WebsiteCrawlSource`** under `src/ingestion/sources/website_crawl.py`. Implements the V1.5a `DataSource` Protocol so it shares lifecycle + tier declaration + scheduling semantics with the DB connectors. Tier defaults to **L2** (official sources) and is user-declared; the user can upgrade individual domains to L1 only if they confirm immutability (matching ADR-014's L1 gating).

**New `Crawl4AIAdapter`** under `src/ingestion/adapters/crawl4ai_web.py`. Wraps `crawl4ai.AsyncWebCrawler` behind the V1 `SourceAdapter` Protocol. Honors robots.txt, sitemap.xml, ETag/Last-Modified, content-hash dedupe. Supports HTML, PDF, image OCR, table extraction. See ADR-019.

**Optional `ScrapingBeeFallback`** — domain-level opt-in proxy under `src/ingestion/adapters/proxy_scrapingbee.py`. Activated only when crawl4ai's local fetch fails with 403/429/503 patterns or DataDome/PerimeterX challenges are detected. See ADR-019.

**Staged graph ingestion** — three opt-in levels per domain. See ADR-020.
- **L0 — sitemap graph** ($0): just `WebPage` nodes + `LINKS_TO` / `BELONGS_TO_SITEMAP` edges. Deterministic, no LLM. Equivalent to V1 Pass 1 for web data.
- **L1 — entity-tagged graph** (~$0, local NLP only): adds GLiNER2-extracted `Entity` nodes + `MENTIONS` edges per page. Equivalent to V1 Pass 2–3.
- **L2 — full web GraphRAG** ($-cost LLM): adds Pass-4-style sentiment / claim / relationship extraction + community detection. Equivalent to V1 Pass 4–5.

The user picks the highest stage they want per domain; higher stages run only after lower stages complete. Stages are idempotent and incremental.

**New scheduler row** in `crawl_jobs` SQLite table; Prefect 3 cron flow runs every 5 minutes, picks up due jobs, marks them running, dispatches to a `Crawl4AIAdapter` worker flow, writes back status. See `data.md`.

**New `Page`, `Sitemap`, `MediaAsset`, `Table` node types** in the graph + `LINKS_TO`, `BELONGS_TO_SITEMAP`, `EMBEDS`, `TABLE_OF` edge types. All bitemporal per V1 ADR-005.

**New domain blocklist + per-domain budget** in `.env` + per-domain settings UI. Forums (Reddit, SDN, etc.) and social-media domains (Twitter/X, Instagram, LinkedIn, TikTok, Facebook, Bluesky, Mastodon, Threads) are hard-blocked at the `register_domain()` call. See ADR-019 §"Domain blocklist".

**New `/ingest/web` UI** under `web/src/app/ingest/web/`. Three pages: domain list, per-domain detail + crawl history, register-new-domain wizard. Backend under `src/web/routes/website_crawl.py`. UI design extends `docs/08-ui/ingestion-wizards.md`.

**New outbound MCP tool surface**: `register_crawl_domain`, `list_crawl_domains`, `get_crawl_status`, `trigger_crawl_now`, `pause_crawl_domain`, `update_crawl_cadence`. Available to the LLM agent + via FastAPI routes.

## Non-negotiables carried from V1 + V1.5

- L1 immutability survives. A domain declared L1 by the user joins the immutable set; an L2-declared domain does not.
- Bitemporal edges + Wikidata-rank schema unchanged for the new `Page` / `Sitemap` / `MediaAsset` / `Table` types.
- Citation traceability ≥ 99% on every retrieval surface, including the new website-graph views.
- Audit log covers every crawl invocation, robots.txt fetch, page download, extraction stage, and HITL escalation. Append-only per ADR-009.
- TDD + Verification Before Completion per AGENTS.md, per sub-slice.
- Browser validation runs for every UI change per CLAUDE.md.
- robots.txt is honored. `User-Agent` is declared honestly (`SecBrain/1.6 (+contact-email-from-env)`).
- Per-domain budget caps in pages and USD; cap-hit pauses the domain and emits a HITL `crawl_cap_hit` item.

## What's deliberately out of V1.6a

- Forums (Discord/Discourse/StackExchange) — V1.6b.
- Slack / Notion connectors — V1.6c.
- Browser-based JS-heavy paywalled sites — handled only when the seed URL works under crawl4ai + ScrapingBee. Deep SSO/login flows are V2.
- Automatic graph schema discovery for unknown entity types — V2; V1.6a uses the V1 schema + GLiNER2 default labels.
- Real-time push (RSS/Atom feeds, WebSub) — V2; V1.6a polls on user cadence.
- Multi-tenant / external user — V2.
