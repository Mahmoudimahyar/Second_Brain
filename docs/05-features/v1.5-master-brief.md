# V1.5 Master Brief

> **Status:** Spec only. Locked 2026-05-24 after Mahyar Q&A round V1.5-R1. Implementation blocked on per-sub-slice TDD per AGENTS.md.
> **Reframe from V1:** V1 was internal-only, single-user, CLI + flat-YAML, 5-source corpus. V1.5 keeps the same engine but adds (a) a generalized external-data connector surface, (b) a web UI for ingestion + HITL + multi-level graph viewing, (c) iterative human-in-the-loop quality refinement, (d) web-search-grounded conflict resolution, and (e) the first three downstream-consumer dashboards.

## What V1.5 is for

V1 proved the trust-tier knowledge-graph architecture works end-to-end on a fixed corpus. V1.5 is the **generalization pass**: the system stops being a "dental knowledge engine" and becomes a **plug-in knowledge-engine framework** where the user brings their own data sources and works the graph iteratively through a web UI. This is the on-ramp to V2's multi-tenant, `developer_tool`-mode product.

V1.5 is still internal-only (single-user, localhost) — the multi-tenant security rewrite stays in V2 per ADR-009. What changes is that V1.5's interface stops being "Claude Code running CLI commands" and starts being "a person in a browser driving the system".

## Architecture deltas from V1

The engine internals stay the same. What V1.5 adds:

**New connector tier above `SourceAdapter`.** V1's `SourceAdapter` Protocol assumes a payload-paths list of files. V1.5 introduces a `DataSource` Protocol that wraps `SourceAdapter` and adds (a) connection lifecycle (open/close), (b) schema discovery, (c) user-driven table/projection selection, (d) tier declaration, (e) periodic re-pull (for live DBs). See `docs/04-architecture/v1.5-connector-architecture.md` (V1.5a deliverable).

**New cross-graph link layer.** V1's entity resolution snaps L5 mentions to L1 canonical entities **within one ingest's universe**. V1.5 adds `CrossGraphLink` edges: external-DB entities link to forum-graph mentions and vice versa. Uses the same DITTO + BGE pipeline with cross-source confidence calibration. See ADR-015.

**New web frontend.** Next.js 15 app under `web/` (new top-level dir), FastAPI backend under `src/web/` (new). Pydantic models shared via Zod schema generation. See ADR-013.

**Iterative feedback loop.** Pass 4 BAML prompts get a `context_block` that loads (a) previously-accepted node/edge types for this corpus, (b) blacklisted types. Each HITL decision writes to a `feedback_log` SQLite table; the BAML loader queries it at Pass 4 init. See ADR-017.

**Web-search conflict agent.** New `src/conflict/web_verify.py` invoked at step 5 of the conflict-resolution order (`docs/04-architecture/system-overview.md` §3). Brave Search API + Tavily API run in parallel; both must return supporting evidence with citations before the verdict is written. See ADR-016.

**Three-tier graph views.** Same underlying graph, three separate retrieval contracts so the UI views stay independent:
- **Level A — structural** (`query_graph_structural`): users, posts, comments, AUTHORED/REPLIED_TO/UPVOTED. Deterministic Pass 1 output.
- **Level B — clusters** (`query_graph_clusters`): cluster nodes + IN_CLUSTER edges + Pass 3 summaries. Aggregation layer.
- **Level C — analyzed** (`query_graph_analyzed`): full graph including Pass 4 extractions + conflict-resolved claims + cross-graph links.

See ADR-012.

## Non-negotiables carried from V1

- L1 immutability survives. ADEA/CODA L1 still cannot be modified by extraction. An external DB declared L1 by the user joins the immutable set; an L2-declared DB does not.
- Bitemporal edges + Wikidata rank schema unchanged.
- Citation traceability ≥ 99% on every retrieval surface, including the three new per-level views and per-team dashboards.
- Audit log covers every UI action (HITL decisions, connector operations, web-search invocations, feedback-loop writes).
- TDD + Verification Before Completion per AGENTS.md, per sub-slice.
- Browser validation runs for every UI change per CLAUDE.md.

## Risks + mitigations

| Risk | Mitigation |
|---|---|
| 12–16 wk effort slips | Sub-slice gates catch slippage early; each can ship independently if scope is cut |
| Web UI is new ground for this repo | ADR-013 picks a battle-tested stack; first V1.5b task is a thin vertical slice (one page wired end-to-end) before broad implementation |
| Cross-graph alignment quality unknowable until tried | V1.5a includes a 100-pair gold set + F1 ≥ 0.92 gate before merging |
| Web-search cost/latency unpredictable | Brave + Tavily both have free tiers; usage capped at N searches/dump; cache results in SQLite |
| BAML prompt-context bloat | Hard cap on context-block size (5kb); cache eviction by recency × decision frequency |
| Plaintext `.env` for DB credentials is risky | V1.5-only allowance — UI shows banner on every credential entry; V2 ADR-014 amendment plans OS-keychain migration |
| User decision fatigue in HITL UI | Each review page shows clear progress (X of Y); bulk-action shortcuts; resume-from-where-you-left-off |
