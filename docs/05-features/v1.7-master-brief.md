# V1.7 Master Brief — Evidence Answer Engine (EAE)

> Status: **In progress** (2026-06-17). Design investigation complete; EAE-1..EAE-7 implementation pending.
>
> Branch: `v1.7-sota-rearch-and-wiring`

## Goal

Turn the existing KB ask agent (`POST /api/v1/ask`) into a full evidence-grounded answer system that:
- Shows **where** evidence comes from (L1 official vs L5 forum vs comments), with typed counts
- Surfaces **tier-weighted reliability** so the most authoritative signal ranks first
- Adjudicates **popular vs correct** when forum consensus disagrees with official data
- Shows the **opinion distribution** (e.g., "80% report positive vibe, 15% neutral, 5% negative")
- Provides **drill-down** to the original source document for every cited claim
- Includes **comment evidence** (1.95M comments currently excluded)

## Context

The canonical graph has: 4,558,352 nodes / 13,103,287 edges / 877K posts / 1.95M comments / 4,750 L1 Claims / 432 ForumConsensus nodes / 640K SentimentAnnotations / 83K Claims / 8K InterviewQuestions.

The V1-June12 bundle ships a portable `documents.sqlite` (3.325M docs) + MCP server for offline use.

The ask agent (`src/retrieval/kb_agent.py`) is wired and smoke-validated but returns a flat answer with no evidence breakdown, no tier weighting in the answer path, and no comment recall.

## The 7 steps (R1–R7)

| Step | ID | What | Key files |
|---|---|---|---|
| 1 | EAE-1 | FTS5 index over documents.sqlite for comment recall | `cloud/add_fts5_documents.py` (patch existing) + `cloud/build_documents_sqlite.py` (updated) — **scripts built; needs VM run + KBAgent wiring** |
| 2 | EAE-2 | EvidenceSet assembler in `KBAgent.retrieve()` — union semantic + comment FTS5 + SDN + L1 + ForumConsensus; tag each item source_type/tier/doc_id/url | `src/retrieval/kb_agent.py` |
| 3 | EAE-3 | Typed-count aggregator: "3 L1 + 47 L5 + 8 Comment" + most_reliable surfacing | `src/retrieval/kb_agent.py` |
| 4 | EAE-4 | `EvidenceAnswer` pydantic schema + `POST /api/v1/evidence` route + `get_node` for L1 Page/Chunk/Claim drill-down | `src/web/schemas/evidence.py`, `src/web/routes/evidence.py` |
| 5 | EAE-5 | Wire `ranking.py` + `consistency.py` into `KBAgent.answer` with `{L1:1.0, L5:0.4}` weight map; emit `verdict.popular_answer` vs `verdict.statement` | `src/retrieval/kb_agent.py`, `src/retrieval/ranking.py`, `src/retrieval/consistency.py` |
| 6 | EAE-6 | Stance clustering (KPA): LLM-match evidence items to canonical positions; emit % + n + example_citation_ids; polarity fallback | `src/retrieval/kb_agent.py` |
| 7 | EAE-7 | Calibrated abstention (abstain_margin from `joint_resolver.py:166`); multi-answer combination verdicts; coverage-vs-selective-accuracy eval set | `src/retrieval/kb_agent.py`, `src/conflict/joint_resolver.py` |

## Dependencies and ordering

EAE-1 (comment recall) MUST be done on EC2 VM — rebuilding documents.sqlite with 3.325M rows risks OOM on local PC.

EAE-2 depends on EAE-1 (FTS5 available).
EAE-3 depends on EAE-2 (typed items in the set).
EAE-4 can run in parallel with EAE-5.
EAE-5 depends on EAE-3 (evidence set assembled before ranking).
EAE-6 depends on EAE-5 (answer + evidence before stance clustering).
EAE-7 depends on EAE-6 (complete answer pipeline before abstention calibration).

## Success criteria

- `POST /api/v1/evidence` returns `EvidenceAnswer` with: `typed_counts`, `most_reliable`, `opinion_distribution`, `popular_answer` vs `authoritative_answer`, drill-down `sources` list (each with `doc_id`, `url`, `source_type`, `tier`, `snippet`).
- Comment evidence included in at least R1/R2 (count visible even if not embedded).
- All 7 steps wired and smoke-tested on the real graph.
