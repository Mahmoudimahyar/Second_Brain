# ADR-004: Prompt Framework — BAML Primary, DSPy GEPA Post-V1

Status: **accepted**
Date: 2026-05-20

## Context

Stage-3 extraction needs a prompt-management layer that:
1. Defines prompts + output schemas in a vendor-portable way (because of ADR-011 multi-vendor gateway).
2. Validates structured output reliably without hand-rolled Pydantic glue everywhere.
3. Allows automatic prompt optimization later (once HITL gold accumulates).

R-004 (R-006 verified) compared BAML, DSPy 2.x → 3.0, Instructor, raw Outlines/Guidance.

## Decision

**BAML 0.222.0+ for V1 production prompts.** DSPy 3.0 + GEPA optimizer for **post-V1** offline prompt tuning once HITL produces ~2-5K gold examples.

### Rationale per choice

- **BAML**: Schema-Aligned Parsing (SAP) gives structured output reliability across vendors via the gateway. Vendor-portable prompt definitions; consumed by any vendor through `LLMClient` ABC. Build step is small (one CLI invocation; output checked in).
- **DSPy 3.0 + GEPA**: GEPA (Aug 2025) replaces MIPROv2 with 35× fewer rollouts. Used as a tuner, not a production prompt-runtime. Activates in V1.x once labeled data exists.
- **Instructor**: kept as a lighter fallback (e.g., for one-off scripts under `tools/`); never the production layer.

### What BAML owns

- Every extraction prompt template (stored as `src/prompts/*.baml`).
- Output schema definitions (Pydantic models generated by BAML).
- Few-shot examples curated alongside the prompt template.
- Prompt-version tracking (every prompt has `prompt_id` + `prompt_version`; version bumps invalidate the extraction cache).

### What the gateway owns (NOT BAML)

- Vendor SDK calls (Anthropic, OpenAI, Google).
- `ttl: 3600` cache pinning (A-036).
- Per-task model routing (ADR-003 addendum).
- Cost telemetry (Langfuse).
- Fallback chains.

BAML compiles the prompt + schema → the gateway executes through the chosen vendor.

## Consequences

- New extraction prompts go through `src/prompts/*.baml` + BAML's CLI to regenerate Python clients. CI step verifies BAML clients are up-to-date with `.baml` source.
- Schema changes invalidate the content-addressable extraction cache (intentional — `schema_hash` is part of the cache key).
- Prompt-version bumps require an entry in the prompt-version changelog (`src/prompts/CHANGELOG.md` — V1 implementation).
- DSPy adoption gated on gold-set growth (GAP-028).
- Adds one build step (BAML CLI) to the dev workflow; documented in `deployment.md`.

## Alternatives considered

- **Instructor alone**: no schema-aligned parsing; output reliability lower; rejected as primary.
- **LangChain prompts**: rejected per `dependency-rules.md` banned list (abstractions duplicate ours, churn fast).
- **Raw Pydantic + provider-side structured outputs only**: works per-vendor but duplicates prompt code across vendors; vendor-portability suffers.
- **DSPy as production runtime**: too much auto-optimization noise during prod operation; better as offline tuner only.
- **Outlines / Guidance / lm-format-enforcer**: provider-side native structured output has overtaken these for API LLM paths. XGrammar wins for local-model paths (ADR-003).
